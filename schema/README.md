# Schema

`world.schema.json` is the **normative** data model of the world
document (L0): entities, shapes, materials, lights, environment, audio,
behaviors, triggers, tours, avatar. It is generated from the reference
type definitions (schemars over the reference Rust crate) — never
hand-edited. Where prose and schema disagree, the schema wins and the
prose gets fixed.

- Manifest schema version: **3**
- Draft spec: **0.3** (the manifest gained an optional `ambience`, so the
  fold's state is always a whole manifest)

The cinematography extension schema is likewise generated from the Rust
reference types, including its 0.4 track definitions:

```bash
cd ../rust
cargo run --example cinematography-schema --features schema > ../schema/extensions/ext-cinematography.schema.json
cd ../schema
```

Its snapshot test fails when the committed schema drifts. This extension
change does not alter `world.schema.json`, schema version 3 or package
format 2.

## The entity-reference marker

Fields that hold an entity reference carry an `x-entity-ref` annotation
(`"bindable"`: a name is accepted at intake; `"id"`: numeric only), set
on the reference Rust crate's fields so the generated schema carries it.
`entity-refs.json` is the machine-readable list of them, generated by
`generate-entity-refs.mjs` — the one list every reference's name
binding, merge rewriting and ingestion validation reads
([spec/world.md](../spec/world.md), "Identity"). Extension schemas
(`extensions/*.schema.json`) mark theirs the same way, and the
generator carries them with the path rooted at the extension's key
(`ext-cinematography/camera/aim_entity`). Regenerate after a schema
change:

```bash
node generate-entity-refs.mjs
```

The session log's entry envelope and op kinds ([spec/session.md](../spec/session.md))
are specified in prose until the state document settles; the `state.json`
schema is an open item ([spec/README.md](../spec/README.md)).

## Using it

Validate a manifest before rendering:

```bash
npx ajv-cli validate -s world.schema.json -d ../conformance/shapes.json
```

The language packages ship these schema files, so consumers validate
against their installed dependency rather than a checkout of this
repository: npm resolves the paths
(`require.resolve("openworldformat/schema/world.schema.json")`),
Python reads them through `openworldformat.schema_path`, Swift
through `schemaURL`, Kotlin through `schemaText` — each package's
README lists them all, and each package's tests fail when its copies
drift from these.
